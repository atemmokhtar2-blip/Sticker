# WhatsApp Sticker Bot — Railway Deployment

خدمة واتساب عامة لتحويل صور المستخدمين إلى ملصقات WhatsApp. يختار المستخدم عند أول تواصل بين **تواصل مع المطور** و**استخدام البوت**، ويحصل كل مستخدم على حد أقصى **12 ملصقاً يومياً**.

## متغيرات التشغيل

| المتغير | مطلوب؟ | القيمة |
|---|---|---|
| `DATABASE_URL` | **نعم** | رابط Neon PostgreSQL الكامل (Connection string) كـ Secret |
| `PHONE_NUMBER` | أول ربط فقط | رقم واتساب بصيغة دولية بدون `+` أو مسافات، مثال: `201XXXXXXXXX` |
| `PORT` | نعم على Railway | Railway تضبطه تلقائياً؛ محلياً استخدم `8080` |
| `NODE_ENV` | اختياري | `production` |
| `LOG_LEVEL` | اختياري | `info` افتراضياً |
| `SESSIONS_DIR` | اختياري | مجلد ملفات الجلسة المحلية؛ الافتراضي `/app/sessions` داخل الحاوية |

**لا تضف** `DB_PATH` أو أي إعداد SQLite؛ المشروع يستخدم Neon PostgreSQL فقط.

## إعداد Neon وRailway

1. أنشئ قاعدة بيانات في [Neon Console](https://console.neon.tech/).
2. من Neon افتح **Connect** واختر قاعدة البيانات والفرع، وانسخ **Connection string**.
3. في Railway افتح الخدمة ثم **Variables** وأضف:
   - `DATABASE_URL` = رابط الاتصال الذي نسخته من Neon، كـ Secret.
   - `PHONE_NUMBER` = رقم واتساب الذي ستربطه أول مرة، دولي وبدون `+`.
4. لا تضع رابط قاعدة البيانات في GitHub أو داخل الكود أو في رسالة عامة.
5. اربط مستودع `atemmokhtar2-blip/Sticker` في Railway ثم نفّذ Deploy.

المشروع ينشئ الجداول تلقائياً عند بدء التشغيل: `settings` و`sticker_users` و`sticker_usage` و`sticker_history` و`whatsapp_sessions`. لا تحتاج إلى تشغيل SQL يدوياً.

## ربط واتساب مرة واحدة

- في أول تشغيل فقط، إذا لم يجد المشروع جلسة مسجلة في مجلد التشغيل، سيطلب كود الربط ويعرضه في **Deploy Logs** بعد نحو 15 ثانية.
- من واتساب: **الإعدادات ← الأجهزة المرتبطة ← ربط جهاز ← الربط برقم الهاتف**، ثم أدخل الكود.
- بعد نجاح الربط تُحفظ نسخة مشفرة/مهيكلة من ملفات جلسة Baileys في جدول `whatsapp_sessions` داخل Neon.
- عند أي Restart أو Deploy جديد، يستعيد المشروع ملفات الجلسة من Neon قبل إنشاء اتصال واتساب. لا يحذف الجلسة عند الانقطاع المؤقت أو التحديث العادي، ولا يطلب ربطاً جديداً ما دامت جلسة واتساب صالحة.
- بعد أول ربط ناجح، يصبح `PHONE_NUMBER` اختيارياً من الناحية التقنية لأن رقم الحساب يُقرأ من بيانات الجلسة المحفوظة؛ اتركه مضبوطاً لتسهيل الاستعادة والتشغيل.
- لا تسجل خروجاً من الأجهزة المرتبطة ولا تمسح بيانات `whatsapp_sessions` في Neon. إذا ألغيت ربط الجهاز من تطبيق واتساب نفسه، فسيطلب ربطاً جديداً.

**مهم للاستقرار:** يوصى بتشغيل نسخة واحدة فقط من خدمة البوت على نفس جلسة واتساب. لا تشغّل نسختين متصلتين بالحساب نفسه في الوقت نفسه.

## طريقة الاستخدام

- عند أول رسالة من أي مستخدم، تظهر له خيارات **تواصل مع المطور** و**استخدام البوت**.
- اختيار التواصل يوقف الرد الآلي في المحادثة حتى يختار المستخدم «استخدام البوت»؛ التواصل يتم على رقم الخدمة نفسه.
- اختيار استخدام البوت يفعّل تحويل الصور إلى ملصقات WebP.
- لكل رقم مستخدم حد يومي مستقل قدره 12 ملصقاً، ويُعاد ضبطه حسب توقيت القاهرة.
- تُسجّل محاولات التحويل ونتائجها لمنع احتساب الرسالة المكررة أكثر من مرة، ويُعاد الرصيد عند فشل التحويل.

## التطوير محلياً

أضف `DATABASE_URL` في بيئة التشغيل، وأضف `PHONE_NUMBER` عند أول ربط:

```bash
pnpm install
pnpm --filter @workspace/api-server run build
PORT=8080 node --enable-source-maps artifacts/api-server/dist/index.mjs
```

## API

- `GET /api/healthz` — فحص الصحة
- `GET /api/bot/status` — حالة الاتصال وكود الربط الحالي
- `GET /api/settings` — الإعدادات
- `PATCH /api/settings` — تعديل `sticker_quality` و`channel_name`

## ملاحظات تقنية

- Node.js 20+.
- Baileys لإدارة جلسة WhatsApp واحدة مشتركة.
- Neon PostgreSQL هو مصدر البيانات الأساسي والوحيد.
- Sharp لتحويل الصور إلى WebP 512×512.
- لا ترفع ملفات الجلسة أو أسرار الاتصال إلى Git.

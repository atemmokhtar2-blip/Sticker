# WhatsApp Sticker Bot — Railway Deployment

خدمة واتساب عامة لتحويل صور المستخدمين إلى ملصقات WhatsApp. يختار المستخدم عند أول تواصل بين **تواصل مع المطور** و**استخدام البوت**، ويحصل كل مستخدم على حد أقصى **12 ملصقاً يومياً** مستقلًا عن بقية المستخدمين.

## النشر على Railway

### المتطلبات
| المتغير | القيمة | ملاحظة |
|---------|--------|--------|
| `PORT` | تلقائي من Railway | مطلوب — Railway تضبطه |
| `PHONE_NUMBER` | `201044568121` | رقمك الدولي بدون `+` — مضبوط افتراضياً في railway.json، أو ضعه في Variables |

### خطوات النشر
1. على Railway: **New Project → Deploy from GitHub repo** ← اختر هذا المستودع.
2. Railway ستقرأ `railway.json` تلقائياً:
   - **البناء**: `corepack enable && pnpm install --frozen-lockfile && pnpm --filter @workspace/api-server run build`
   - **التشغيل**: `node --enable-source-maps artifacts/api-server/dist/index.mjs`
   - **healthcheck**: `/api/healthz`
3. **ضروري قبل تشغيل الخدمة العامة:** فعّل Persistent Volume على Railway واربطه بمجلدي `/app/sessions` و `/app/data`. مجلد sessions يحتفظ بتسجيل دخول واتساب، وقاعدة البيانات داخل data تحتفظ بنسخة احتياطية من الجلسة وحصص المستخدمين. لا تحذف المجلدين ولا تمسح بيانات الجلسة عند إعادة النشر. إذا لم يتم تركيب Volume فليس هناك ضمان لاستمرار الجلسة بعد إعادة إنشاء الحاوية.

### الحصول على كود الربط (8 خانات)
- عند أول نشر، يظهر **كود الربط** (8 أرقام/أحرف) في **Deploy Logs** بعد ~3 ثوانٍ من بدء التشغيل.
- شكله في الـ log: `WHATSAPP PAIRING CODE: XXXXXXXX — open WhatsApp > Linked Devices > Link a Device > Link with phone number`
- في واتساب: الإعدادات ← الأجهزة المرتبطة ← ربط جهاز ← **رابط برقم هاتف** ← أدخل الكود.

### بعد الربط
- عند أول رسالة من أي مستخدم، تظهر له خيارات **تواصل مع المطور** و**استخدام البوت**.
- زر التواصل يحوّل المستخدم إلى محادثة رقم الخدمة نفسه؛ عند اختيار التواصل يتوقف الرد الآلي في هذه المحادثة حتى يختار المستخدم العودة إلى البوت.
- عند اختيار استخدام البوت، يرسل المستخدم صورة ليتم تحويلها إلى ملصق WebP.
- الحد اليومي 12 ملصقاً لكل رقم مستخدم، ويُعاد ضبطه يومياً حسب توقيت القاهرة.
- لا يُخصم الاستخدام عند فشل التحويل أو إرسال الملصق.
- يتم حفظ المستخدمين والعدادات في SQLite، وتُحفظ نسخة من ملفات جلسة واتساب في قاعدة البيانات عند الاتصال وتحديث بيانات الاعتماد والرسائل الواردة.

### إعادة الربط
احذف محتوى مجلد `sessions/` (عبر Persistent Volume) ثم أعد النشر ليظهر كود جديد.

## التطوير محلياً
```bash
pnpm install
pnpm --filter @workspace/api-server run build
PORT=8080 node --enable-source-maps artifacts/api-server/dist/index.mjs
```

## API
- `GET /api/healthz` — فحص الصحة
- `GET /api/bot/status` — حالة الاتصال + الكود الحالي
- `GET /api/settings` — جميع الإعدادات
- `PATCH /api/settings` — تعديل الإعدادات (`sticker_quality`, `channel_name`)

## ملاحظات
- يتطلب Node.js 20+ (محدد في `package.json` engines).
- يستخدم `@whiskeysockets/baileys` للاتصال بواتساب (Pairing Code).
- يستخدم `sharp` لتحويل الصور إلى WebP 512×512 + `better-sqlite3` للإعدادات.
- **لا يتم تعديل الصورة أبداً** — الوصف يظهر كـ caption أسفل الملصق فقط.
- `sessions/` و `data/*.db` تُنشأ وقت التشغيل ولا تُرفع إلى git.


## ملاحظات تشغيل الخدمة العامة
- يستخدم المشروع حساب WhatsApp واحداً متصلاً، وتتم معالجة صور جميع المستخدمين من خلاله؛ لا ينشئ جلسة واتساب منفصلة لكل مستخدم.
- الجلسة الحالية لا تُمسح تلقائياً عند إعادة التشغيل أو انقطاع الاتصال المؤقت. إذا ظهر تسجيل خروج فعلي من واتساب، فقد يتطلب الأمر ربطاً جديداً يدوياً.
- أزرار واتساب التفاعلية تعتمد على دعم عميل واتساب؛ عند تعذر إرسالها يرسل البوت تعليمات نصية بديلة.
- حد الاستخدام وسيلة لتنظيم الخدمة وليس ضماناً ضد تقييد الرقم. يجب الالتزام بسياسات واتساب، وتجنب الرسائل المزعجة، ومراقبة مؤشرات الحساب.
